# Solutioning Standards

Routes design.md to the solutioning knowledge. How to build it is governed by
`docs/agents/development-standards.md`.

## How to use this file
- Read it before writing or revising design.md, and in /opsx:explore when the exploration
  weighs how to solve something or needs the current system state.
- Always read `docs/solutioning/principles.md`. Then read the topic file for each topic the
  design considers: only those.
- A topic file may make a principle more specific. It MUST NOT contradict it. On a conflict,
  principles.md wins and the conflict is reported.
- If a topic has no file, apply principles.md alone and state the gap in design.md.
